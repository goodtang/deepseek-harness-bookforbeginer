# DeepSeek Harness 教学书实施安排：上下文与连续性

日期：2026-11-10。依据：[V6 方案](deepseek-harness-book-plan-v6.md)。本安排规定怎样执行 V6，不增加教材目标或新的总体版本。

## 目标与使用入口

优先保证相邻章节有充分上下文，同时让术语、代码、图、业务数据和验证结论在跨会话写作中保持一致。执行入口为 [START-HERE](book-work/START-HERE.md)，当前进度为 [STATE](book-work/STATE.md)。这些文件是工作记录，不能替代真实正文、源码和验证证据。

当前只完成执行安排与接续资料初始化。样章、脚手架和运行实验仍未交付，不因文件建好而报告通过。

## 一、上下文的读取顺序

| 优先级 | 读取材料 | 用途 |
| --- | --- | --- |
| 1 | 当前用户指令、适用 AGENTS、START-HERE、STATE、HANDOFF | 确认本次任务、未完成工作与权限 |
| 2 | 上一章已确认正文、实验起点、图注和章末交接 | 确认学生实际已经学会什么 |
| 3 | 当前章完整正文、交接表、代码、图源与证据 | 保持当前内容的准确与连贯 |
| 4 | 下一章已有正文；尚未写作时读取大纲、前置条件与交接目标 | 确认当前章必须提供什么，避免提前堆知识 |
| 5 | 本次涉及的真实源码、测试、配置及权威文档 | 核对机制与实际行为 |
| 6 | 共享术语、概念位置、代码演进与业务需求记录 | 防止跨篇漂移 |
| 7 | 其他章节与历史讨论 | 仅在依赖或冲突出现时定点读取 |

默认以上一章、当前章、下一章组成相邻写作范围。已经存在的相邻正文优先读原文，不仅凭摘要续写；未写出的下一章不能假称已经完整读取。远处章节通过稳定索引定位，涉及其承诺时再读相关原文。

跨篇依赖可能比临近章节更重要，例如早期权限定义影响后期业务写入。此时将该定义及原始依据加入必读集合，不能以“不是相邻章”省略。

## 二、容量不足时缩小任务，不削掉关键依据

不假定工具能准确报告剩余上下文，也不依赖自动压缩摘要保存全部知识。每轮开始先评估材料体量，留出检查、工具输出和交接所需空间。无法充分容纳时，不尝试一次完成整章。

默认一个任务只完成一个可验收的小节或实验，例如“查询函数接入真实工具的注册与参数处理”。输出需要同时包含对应文字、代码、图与验证状态，避免只完成文字后遗忘待核实内容。

若三章全文加当前源码过大，先完成三章的连续阅读与交接检查，再为小任务读取上一章相关完整段落、当前小节及其必要上下文、下一章对应段落，并登记实际读取范围。全文仍保留在磁盘，不把压缩后的摘要当作原文。完成小任务后另做连续性复核，不能声称始终同时持有全部正文。

出现反复查找已定术语、混淆版本、说不清实验状态等迹象时，先停止扩写、保存检查点，再重新读取依据。禁止为了赶进度猜测缺失细节。

## 三、持久记录与单一事实来源

| 材料 | 保存位置或建立时机 | 规则 |
| --- | --- | --- |
| 总体要求 | V6 | 修改教学目标须有明确依据；执行记录不能偷偷覆盖要求 |
| 稳定约定 | [CANON](book-work/CANON.md) | 已确认规则与来源，新增约定标明性质，不把推测写成事实 |
| 章序与依赖 | [CHAPTERS](book-work/CHAPTERS.md) | 稳定章节 ID、前后关系、首次教学与回访位置 |
| 当前状态 | [STATE](book-work/STATE.md) | 已完成、未完成、阻塞及下一步，链接证据 |
| 接续检查点 | [HANDOFF](book-work/HANDOFF.md) | 当前任务、读过的范围、改动、未执行检查、下一动作 |
| 每章工作包 | 按[工作包模板](book-work/chapter-task-template.md)在首次开写时创建 | 保存交接、源码依据、代码版本、图与验证状态 |
| 实验与原始证据 | 章节工作包指定独立目录 | 正文只展示必要结果，完整输入输出和清理记录可追踪 |

源码行为以对应基线的实现和测试核实。实验结果以原始证据为准。总结与接续文件帮助定位，不拥有改写这些事实的权力。

业务工单、查询函数、工具名称、类型字段和图例在首次确定时进入共享约定并链接实际定义。没有确定的字段写“尚未确定”，不能在后续章节各自发明。改名或改变含义时记录受影响章节、代码、图及实验。

## 四、实施顺序与可验收工作包

### E0：接续资料初始化

- [x] 建立本安排、接续入口、状态、稳定约定、章序索引和交接模板。
- [x] 明确现有规划已就绪，样章与实测仍待完成。
- [ ] 首次实际任务开始时，记录将使用的源码与材料指纹。

本阶段不是 M0 或 M1 验收通过，只表示具备文件化接续方式。

### E1：为《第一个业务工具》准备实际接入与证据

- [ ] 读取查询函数前章的交接目标和循环后章的大纲。正文未写时明确缺口。
- [ ] 在章节工作包确定初学者已具备知识及必要补课，不用已有完整前章的假象掩盖准备不足。
- [ ] 核实真实 profile、工具注册与模型模拟设施，补齐最小接入工程。
- [ ] 确定工单数据、查询函数与工具输入输出的统一定义。
- [ ] 保存源码坐标、配置与运行版本，核实额外模型调用归属。

交付一套可运行的最小接入工程及实际观察，不仅是命令清单。只在样章范围建立必要清单，不等待全仓库盘点完毕才开始。

### E2：交付完整样章

- [ ] 按小任务完成正文、实际源码、代码改动、图与正常工具循环。
- [ ] 独立验证断流及主动取消，记录触发条件、断言、退出与清理。
- [ ] 章内呈现预测、作者实测、学生复现、差异解释与适用范围。
- [ ] 检查插件职责、依赖、扩展选择和资源归属。
- [ ] 完成单章读者试读并如实记录；尚无试读者时保留待验收。

M1 的两篇样章与工程、读者条件仍按 V6 执行。这里先让业务工具样章落地，不增加新的前置门槛。

### E3：验证相邻三章的连续性

- [ ] 以查询函数、真实工具、请求循环形成连续片段，补齐实际正文与代码版本。
- [ ] 从前章输出逐章继续，检查新增概念和代码改动，不用重置到准备好的终态代替演进。
- [ ] 同一初学者连续试读，记录回翻、提示、失败与独立完成情况。
- [ ] 处理关键知识跳跃，再进入 M2 批量扩写。

本阶段在 M1 之后执行，不阻塞第一篇真实样章产出。

### E4：按相邻范围滚动扩写

当前章通过后，写作范围向后移动一章。上一章保持为已确认输入；当前章保持小任务推进；下一章明确交接目标。每篇结束进行跨章术语、代码、图与业务要求复核。

默认单一写作者顺序推进正文，不同时独立编写相邻章节。只有明确获准的并行任务才采用委派，并给定共同基线与输入输出；外部返回内容需合并复核后才能算入正文。

## 五、每轮工作怎样开始与收尾

开始时读取接续入口与状态，核对当前文件、代码基线和上次交接。Git 提交只能标识已提交代码；未提交和未跟踪的书稿、图源与示例还需保存路径和 SHA-256，避免读取到不同版本却误用旧结果。

随后确认本轮唯一交付物、必读范围、预期检查和相关依赖。实际运行前核对实验环境与自有资源，保持用户配置和已有任务不受影响。

收尾时保存文件与实际证据，分别更新工作包、STATE 和 HANDOFF。明确哪些已验证、哪些仅写好、哪些尚未执行。正文改动后只重跑与改动有关的必要检查；不把旧版本的成功记录自动沿用到新代码。

需要提交业务源码或发布教材时遵循当次授权，不因本安排要求“持久保存”而自动提交或推送业务仓库。MyMem 按既有授权做增量归档，完整原始资料按范围保留；接续摘要不能替代完整资料。

## 六、跨会话与上下文压缩后的恢复

在阶段结束、切换章节或准备结束当前会话时写 HANDOFF，不等到上下文已经不足才开始。意外中断后，下一轮先检查文件与记录，未被证据确认的工作标为未知。

恢复顺序为：当前指令 → START-HERE → STATE → HANDOFF → CANON 与章序 → 当前工作包 → 相邻正文与实际代码 → 上次证据。先用自己的话核对“正在完成什么、前章教过什么、下一章需要什么、哪些检查未做”，有冲突就读原始材料解决，再继续写作。

不要仅凭聊天中的“完成了”更新状态。中断时存在运行中的进程，先核查身份和状态，不擅自重跑可能产生重复副作用的操作，也不结束其他任务。

新聊天不会保证自动读这些文件。用户或调用方需要提供接续入口；同一工作区内的后续任务也应主动按入口恢复，不能宣称后台监控或永久记忆。

## 七、变更影响与一致性检查

改变前章的概念、字段、代码或图时，沿依赖索引检查全部受影响章节，不能只检查相邻两章。将相关结果标为“待复核”，保留旧证据和适用版本；通过复核才恢复相应状态。

每次当前章收尾至少检查：前章输出可被本章使用；本章依赖已有解释；关键术语、代码和图一致；实际结果支持正文结论；章末成果足以支持下一章。涉及插件能力时额外检查职责、服务、扩展点与释放。

每篇结束核对一次业务主线及三个综合项目，防止顺序调整后权限、确认、幂等、未知结果、部署和升级被遗漏。技术和编辑分开检查：代码运行不证明教学连贯，文笔流畅也不证明实现正确。

## 八、本安排的完成与执行状态

本轮交付执行安排与初始接续资料，并检查链接和记录之间的一致性。没有编写真实样章、完成接入工程或运行教材实验。

下一项实际工作是 E1 的样章接入核实与最小工程。上下文管理从该任务开始记录实际文件、基线、证据和交接；本安排不保证零遗漏，而是使遗漏可检测并能依据原件恢复。
