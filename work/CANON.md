# 教材共享约定

读者环境规则（2026-11-11）：书稿与源码的位置、名称、父目录、盘符不能预设成作者布局。读者命令先取得各自实际根目录并校验，再以变量/路径组合复用；实际作者路径只作证据出处。区分文件位置适配、终端语法和平台运行支持，不把 Windows 实测泛化到其他系统。

当前权威要求为 [V6](../planning/book-plan-v6.md)。此文件仅记录高频约定与来源；与 V6 冲突时先核对并纠正执行记录。

核心定位（用户于 2026-11-11 再次确认）：本书固定以 [goodtang/deepseek-harness-local](https://github.com/goodtang/deepseek-harness-local) 这个具体工程为学习和开发对象。最终成果是读者能理解其真实源码与设计，掌握插件、任务控制、数据、交互和分层实现，并能基于该工程按业务需要扩展、调试、验证与交付。每项技术结论绑定所研究的源码版本，不能把别的框架经验直接写成该工程的实现事实。

逐章检查四件事：解决该工程中的什么问题；对应哪些真实代码、配置或机制；怎样验证；为二次开发增加什么能力。基础章围绕实际运行和后续源码学习补课，工作包记录具体用途与回访位置，不为满足形式提前堆源码。独立教学函数与模拟设施需标明职责，并接回真实工程；不能用教学设施的实现代替对工程本身的解释。范围与进度仍按 V6 和章节索引管理，不增加总体方案版本。

- 读者为零基础学生，基础知识在依赖前解释；不能把见过配置等同已理解。
- 一切皆插件贯穿全书；普通函数、库、插件及独立教学循环分别标记。
- 主线为企业问题处理助手，先只读查询，再控制写入与协作，最后交付应用。
- 每章保留预测、作者实测、学生复现、差异解释与结论；第三方报告独立标记。
- 配图有来源、简化范围与图例，图、代码、正文及实验版本对应。
- 连续三章验证在 M1 后、M2 批量扩写前，不阻塞第一篇闭环样章产出。
- 用户希望达到渐进、自学、独立编程和阅读陌生实现的教学效果，不构成一周掌握的承诺。
- 正式第一章为 CH-OBS《一句请求发出去以后》：先依据实测观察，不要求预先安装。后接 CH-RUN《第一次自己运行》解释运行基础，再进入 CH-FUNC；与 V6 第一篇顺序一致，不能直接从观察跳到函数而漏掉运行基础。CH-TOOL 保持独立的部分试写。
- 第二章已写出正式初稿，以两个仓库的文件定位、目标源码最小预检和实际观察命令为内容。预检是教材设施，不能替代目标工程安装、构建或健康检查；已有依赖下的复现与全新环境准备分别验收。后续所有命令继续说明在哪个目录执行、哪项路径指向书稿或源码、结果写在哪里。
- 源码研究基线为 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`；实际任务启动时仍须核对工作树。

E1 已确定：普通函数 `lookupTicket(id)` 位于 [tickets.mjs](../labs/first-tool/tickets.mjs)，返回副本或 `null`。工单为虚构的 `TK-1042`，状态 `open`，标题 `Invoice export failed`；工具名为 `book_ticket_lookup`，必填字符串参数 `id`，规范输出为工单对象或 `null`，render 才转成 JSON 文字块。精确运行命令和配置以[实验说明](../labs/first-tool/README.md)为唯一维护位置。影响 CH-FUNC、CH-TOOL、CH-LOOP 及后续业务项目，不得换名另造一套数据。

本轮模型序列 `tool_call_success,success`，不重复最后行为，显式关闭自动标题生成；源码启动隔离目录必须指定仓库 tsconfig。默认复现输出位于忽略目录，已发布证据单独保留。两次主任务请求的结论只适用于此配置，不推广到默认组合。

第一章的观察摘要由 labs/observe-task 在运行结束后读取真实实验结果再生成，不是实时日志、模型自述或 Harness 的新事件类型。原始断言、摘要与各自代码哈希分开保留；阅读记录与独立运行是不同的学生状态。

2026-11-11 修订版另保存 headless 实际 stdout 为 terminal-stdout.txt，并与观察摘要分开。正文的任务文本、工具结果和终端答复需与同版证据核对；模拟服务的配置字符串不能代替实际采集输出。证据按日期新增，旧记录不套用到改变后的代码。
