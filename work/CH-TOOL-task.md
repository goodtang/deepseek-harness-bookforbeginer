## 实施与检查

先创建普通函数，再将其接入真实插件注册；运行器只驱动 profile 与模拟服务，未直接调用工具 execute。模拟行为只规定名称、参数和完成回答，不提供工单查询结果；第二次请求中的结果由真实管线执行产生。结构化对象经 schema 检查，render 才转换为文本。

首次隔离目录启动失败，0 次模型请求，日志指向 Cordis 导出解析；源码 tsconfig 的注释明确说明 tsx 使用其 workspace paths。给子进程显式指定 TSX_TSCONFIG_PATH 后启动通过。早期失败和过渡版本证据保留，最终版本重新运行通过，不能把早期字符串输出版本证据套给最终对象输出版本。

最终断言：schema 真实出现在第一次请求；两次行为严格匹配；第二次请求的调用参数与结果精确一致，调用编号匹配且非错误；进程退出码单独检查；函数缺失/原型属性名称/副本隔离检查。服务 close、直接子进程退出和临时目录删除均有证据。断流、主动取消、外网隔离、非法参数拒绝、插件注销和真实服务未验证。
